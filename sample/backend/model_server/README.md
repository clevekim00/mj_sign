# SignGemma-Compatible Mock Server

This FastAPI service is a contract-validation backend for SignBridge. It accepts
the `GpuInferenceRequest` envelope, decodes protobuf landmark batches, resolves
the requested model profile, and returns a SignGemma-compatible recognition
response.

## Local Run

```bash
cd sample/backend/model_server
../scripts/setup_mock_venv.sh
.venv/bin/python main.py
```

The generated Python protobuf module requires a runtime compatible with the
checked-in schema code. Use the project-local `.venv` instead of relying on a
globally installed `protobuf` package.

Health checks:

```bash
curl -fsS http://127.0.0.1:8000/health
curl -fsS http://127.0.0.1:8000/ready
```

## Docker Run

```bash
docker build -t sign-gemma-mock ./sample/backend/model_server
docker run --rm -p 8000:8000 sign-gemma-mock
```

The repository stack files build this image automatically:

```bash
docker compose -f docker-compose.stack.http.yml up -d --build
```

The full HTTP stack can be smoke-tested from the repository root:

```bash
./scripts/verify_docker_http_stack.sh
```

That script validates Docker build/startup, Spring readiness, model profile
discovery, text-to-sign synthesis, and WebSocket protobuf streaming.

## Real Recognition Engine

The checked-in server defaults to a mock recognition engine for contract tests.
A trained checkpoint is intentionally not stored in Git. To attach a real
landmark-to-text model, provide a Python factory and mount the checkpoint:

```bash
docker build -f Dockerfile.real -t sign-recognition-real .
docker run --rm -p 8000:8000 \
  -e SIGN_RECOGNITION_ENGINE_FACTORY=my_engine:create_engine \
  -e SIGN_RECOGNITION_CHECKPOINT_PATH=/models/checkpoint \
  -v /absolute/model/directory:/models:ro \
  sign-recognition-real
```

The factory receives the checkpoint path and returns an object whose recognition
method has this contract:

```python
def recognize(*, chunk, profile) -> tuple[str, float]:
    ...
```

`/ready` returns HTTP 503 until the configured factory and checkpoint load.
Add provider-specific packages to `requirements-real.txt`; keep weights,
datasets, caches, and generated artifacts outside the repository.

## Regenerating Protobuf

When `sign/common/schema/landmark.proto` changes, regenerate the checked-in Python module
and Flutter protobuf models from the repository root:

```bash
./scripts/regenerate_protobuf.sh
```

The script also copies the canonical schema into `sign/backend/bridge/src/main/proto`.
Spring Java classes are generated by Gradle during the backend build.

For the Python mock schema only, run:

```bash
./scripts/regenerate_mock_protobuf.sh
```

## Profiles

The mock registry currently exposes Korean/KSL and English/ASL routes plus
additional language placeholders. SignBridge uses these values to validate
`locale`, `sign_language`, and `model_profile` routing before an official
SignGemma artifact is attached.
